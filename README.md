# DSH KOOK · 图片增强版

通过 KOOK 私聊和文字频道使用本机的 DeepSeek Harness（DSH），支持连续对话、图片理解，以及把工作目录中的图片发回聊天。

本项目是 [kaiheila/dsh-kook](https://github.com/kaiheila/dsh-kook) 的社区 Fork，基于官方 `0.3.4` 适配 **DSH `0.2.2-rc.5`**，并增加图片收发能力。使用 KOOK 官方 WebSocket 接口直连，无需额外部署 Satori 网关或公网回调服务。

> 本轮开发版本：`0.3.4-local.rc5.8`，位于 `feature/mention-wakeup`，在现有适配、图片和设置优化基础上增加 @机器人唤醒；尚未合并到 `main`。`main` 目前为此前的 rc5.5 集成版本。本版本未发布到 npm，也未发布 GitHub Release。请按下文从源码构建并安装。

## 功能

| 能力 | 说明 |
| --- | --- |
| 私聊与频道对话 | 指定用户、指定频道白名单；频道支持 @机器人唤醒、命令前缀或自动转发 |
| @机器人唤醒 | 默认开启；在客户端实际选择当前机器人后发送正文，保留原前缀入口 |
| 连续会话 | 保存会话映射，后续消息恢复原 DSH 会话；频道按用户隔离 |
| 图片理解 | 支持普通图片和 KOOK 客户端发送的图片卡片，交给支持图片的模型 |
| 带问题发图 | 同条 @机器人、图片与问题直接识图；分开发送时使用 `/image <问题>` 的两分钟接图流程 |
| 图片回复 | 通过 `send_kook_image` 将工作目录内的图片发送到当前聊天 |
| DSH 工具 | 由所选 Agent 预设提供，例如文件处理、网络搜索；插件本身不内置搜索引擎 |
| 模型选择 | 可指定供应商与模型，或跟随 DSH 默认模型及推理等级 |
| 其他已有能力 | 行为设定、长期记忆、知识文本导入，以及可选的陌生人配对审批 |

DSH 所在电脑需要保持开机、联网。KOOK 对话使用本机配置的模型服务，相关费用按模型供应商规则计算。

| 项目 | 要求 |
| --- | --- |

## 安装

### 1. 获取源码并构建

```sh
git clone --branch feature/mention-wakeup https://github.com/SherryXXX8043/dsh-kook.git
cd dsh-kook
npm ci --ignore-scripts
npm run build
npm test
npm run check
npm pack --ignore-scripts
```

成功后，项目根目录会生成：

```text
dsh-kook-0.3.4-local.rc5.8.tgz
```

仓库中的 `dist/`、依赖目录和本机诊断产物不提交到 Git。构建和安装可能需要联网下载依赖，安装包不是离线依赖合集。

### 2. 在 DSH 中安装

1. 打开 **插件 → 安装**。
2. 输入刚生成的压缩包的**绝对路径**，例如：

   ```text
   C:/Projects/dsh-kook/dsh-kook-0.3.4-local.rc5.8.tgz
   ```

3. 完成安装并启用插件，刷新 DSH 页面。
4. 从 DSH 左下角用户菜单打开 **设置 → KOOK**，填写机器人配置。

插件详情页用于查看版本、启用或停用、卸载和文档入口；原来的整页配置表单迁至 **设置 → KOOK**。插件详情页只保留简洁的配置入口指引。

也可以在安装依赖、构建后，用项目目录的绝对路径进行目录安装；安装后请保持该目录位置不变。压缩包方式更适合固定版本使用。

不要用 `dsh-kook@0.3.4-local.rc5.8` 安装：它没有发布到 npm。官方 `dsh-kook@0.3.4` 是另一个版本，其宿主版本要求不同。

## 首次配置

### 准备 KOOK 机器人

1. 打开 [KOOK 开发者平台](https://developer.kookapp.cn/)，创建应用和机器人。
2. 选择 **WebSocket** 连接模式，获取 Bot Token。
3. 通过机器人的邀请链接将它加入服务器，授予查看目标频道、发送消息等必要权限。
4. 在 KOOK 客户端开启开发者模式，右键复制自己的用户 ID；频道使用时还需要复制文字频道 ID。

### 填写插件设置

打开 **设置 → KOOK**。rc5.4 将完整表单放入 DSH 设置面板，按用途紧凑分组，使用宿主主题颜色；不常用选项放在高级折叠区域。设置页与此前插件详情页使用同一个 `kook` 配置，已有 Token、工作目录、用户和频道白名单、模型选择等继续保留，无需迁移或重新填写。

已保存的 Token 不会回显：输入新值可替换，留空保留现有值；需要清空并停用连接，或改用环境变量时，请选择对应操作后保存。页面不新增机器人在线状态展示，保存成功只表示配置已接受，不等于已确认连接在线。

| 配置项 | 首次测试建议 |
| --- | --- |
| Bot Token | 在本地插件配置页填写；不要提交到仓库或公开发送 |
| 工作目录 | 选择 DSH 主机上已存在的目录 |
| 允许的用户 ID | 填入自己的 KOOK 数字用户 ID |
| 允许私聊 | 开启 |
| 允许的频道 ID | 先留空，私聊成功后再添加 |
| @机器人唤醒 | 默认开启；允许在白名单频道实际 @当前机器人后对话 |
| 自动转发频道消息 | 公共频道建议关闭，避免普通聊天也进入 DSH |
| 命令前缀 | 默认 `/dsh`，可以自定义 |
| 模型与 Agent 预设 | 先跟随 DSH 默认；看图时确认模型支持图片 |

保存后，在 KOOK 私聊机器人发送“你好”。收到回复后再测试连续对话和图片。

要让其他服务器成员使用，需把相应用户和频道加入白名单。仅填写频道 ID 不代表对全服务器开放。陌生人配对功能是可选项，需配置主人 ID 并明确启用。

**保存配置会停止当前 KOOK 任务并重连。** 请等本轮回答结束后再保存。包名和 `kook` 配置身份沿用上游，同一个 Bot Token 只运行一个插件实例。

## 使用命令

下表以默认频道前缀 `/dsh` 为例。自定义前缀后，请替换频道命令的第一段。开启“@机器人唤醒”时，也可以用客户端实际选中的 `@机器人` 替代频道命令前缀，例如 `@Nemo 你好`、`@Nemo /status`、`@Nemo /stop` 或 `@Nemo /new`。这里的 `@Nemo` 是示意，应从 KOOK 提及列表中选择你的机器人。

新开关 `mentionWakeup` **默认开启**，位于 **设置 → KOOK → 访问权限**。它只识别直接提及当前机器人，不按昵称匹配；手工输入普通文字“@Nemo”、@其他人、@所有人或 @角色都不会作为直接提及唤醒。只发送真正的 `@机器人` 而没有正文时，会返回帮助，不启动空白模型对话。

**公共频道推荐关闭“自动转发频道消息”，同时开启“@机器人唤醒”。** 这样大家的普通聊天不会自动进入 DSH，被直接 @时才处理；原 `/dsh` 或自定义前缀仍可使用。发送者和频道都必须在各自白名单中，@不会绕过权限，也不改变现有按用户隔离会话的方式。私聊仍可直接发送文字和图片，不需要 @，不受该频道开关影响。

| 操作 | 私聊 | 频道 |
| --- | --- | --- |
| 文字聊天 | `你好` | `/dsh 你好` |
| 查看帮助 | `/help` | `/dsh /help` |
| 查看会话 ID 与状态 | `/status` | `/dsh /status` |
| 停止当前任务、取消待处理图片 | `/stop` | `/dsh /stop` |
| 下一条消息建立新会话 | `/new` | `/dsh /new` |
| 提问并接收下一张图 | `/image 请分析截图中的报错` | `/dsh /image 请分析截图中的报错` |
| 查看长期记忆 | `/memory` | `/dsh /memory` |

开启自动转发后，白名单用户在白名单频道中的普通消息也会进入 DSH。审批、计划确认和交互式问题仍需要在本地 DSH 界面完成。

## 图片使用方法

### 发图给模型

#### 场景一：频道同一条消息中 @机器人、发图并提问

开启“@机器人唤醒”（默认开启）后，在 KOOK 输入 `@`，从候选列表中选择**机器人账号**，在同一条待发送消息中添加图片并填写问题，例如：

```text
@Nemo 请描述这张游戏截图中的人物。
[同一条消息附带图片]
```

发送后，图片和问题一起提交给 DSH，**无需先发送 `/image`**。请确认选择的是机器人账号，而不是名为“Nemo”的同名角色；两者在 KOOK 中可能都显示为蓝色提及，但角色提及不会触发机器人。发送者与频道仍需在白名单中。

当前图片消息自带的问题优先于旧的待接图问题；如果同一条附图消息写成 `@Nemo /image 请读出图中文字`，也会直接处理这一条的图片，不再等待下一张。**也支持同一条消息只 @机器人并附图、不填写问题**：机器人会结合上下文查看图片，没有其他问题时简要描述。

#### 场景二：先提问，再单独发送图片

如果准备分开发送，先实际选择机器人账号并发送：

```text
@Nemo /image 请分析这张截图。
```

也可以继续使用命令前缀：

```text
/dsh /image 请分析这张截图。
```

收到接图提示后，再由**同一个账号、在同一个频道、于两分钟内**发送图片。接图请求只消费一次。单独发送 `@机器人 看看这张图` 不会自动等待后续独立图片，分成两条消息时应使用 `/image <问题>`。

#### 场景三：私聊

私聊可以直接在同一条消息中发送图片和问题，**不需要 @**；也可以直接发图后继续追问。若准备先提问再单独发图，可先发送 `/image <问题>`，收到提示后在两分钟内发送图片。

开启自动转发的频道也可以直接发图，仍受用户与频道白名单限制。图片会下载、校验并保存为 DSH 原生附件，后续恢复会话可回读，不依赖原始图片 URL 持续有效。支持 KOOK 普通图片（`type: 2`）和客户端包装的图片卡片（`type: 10`）；同一图片卡片中的文字与图片一起处理，分开发送的独立事件不会自动合并为一轮。

**处理失败后如何重试**：同条发送方式请重新选择机器人账号，把图片和问题作为一条新消息发送；两步方式请重新执行 `@机器人 /image <问题>` 或前缀命令，再发图。先检查 KOOK 是否已经收到回复，避免在结果未确认时重复发送。

### 让机器人发回图片

例如，工作目录中已有 `output/chart.png`，可以发送：

```text
请把 output/chart.png 作为图片发给我。
```

当前 KOOK 会话可调用 `send_kook_image`，先用当前机器人上传，再作为图片消息发回当前聊天。它只允许发送配置工作目录内的图片，不能选择其他接收者，也不能读取目录外的符号链接目标。

助手回复中的 Markdown 图片链接或本地路径不会自动变成图片消息。工具负责发送已有图片，不负责生成图片；生成或截图能力取决于当前 Agent 预设提供的其他工具。

### 格式与边界

- 支持 PNG、JPEG、WebP、GIF；**单张最多 8 MiB**，这是插件限制，同时遵守 DSH 的尺寸、数量和总字节限制。
- 当前 DSH 会将动图规范化为静态图，不提供逐帧理解。
- 只从 `img.kookapp.cn`、`img.kaiheila.cn` 的 HTTPS 地址下载图片，不跟随重定向；任意图片网址、引用消息不会自动作为图片输入。
- 图片卡片仅提取支持位置的图片和文字，不执行按钮或其他交互模块；无图卡片不转发。
- 上传或发送结果未确认时，不自动重发；请先查看 KOOK，避免重复发布。
- 普通文件、语音、视频及任意卡片交互尚未支持。

## 模型与会话行为

选择“跟随默认”时，创建或恢复会话会读取 DSH 当前默认供应商、模型和推理等级。显式指定模型时，使用该模型的默认推理等级，不继承其他模型的全局等级。

**从磁盘恢复旧 KOOK 会话时，插件会应用当前配置，覆盖该会话原先保存的模型与推理等级。** 如果该会话已经由本地 DSH 界面打开，插件会在工作目录与预设一致时借用同一个活跃 Agent，继续原历史，不重新挂载预设或覆盖模型选择；更改的插件模型配置需等该活跃 Agent 关闭后冷恢复，或使用 `/new` 建立新会话。

运行中的会话不会随 DSH 全局默认变化立即切换。保存插件配置会停止插件自己创建的 Agent；对本地界面拥有的借用 Agent，仅解除 KOOK 绑定，不销毁其本地任务。明确发送 `/stop` 仍会停止当前共享会话的任务，`/new` 则解除当前 KOOK 路由、保留旧本地会话。更换工作目录或 Agent 预设后，可能需要发送 `/new`。借用期间，本地界面和 KOOK 是同一条会话，其助手回复可能回传到对应 KOOK 聊天。

`/new` 不删除旧会话记录。默认路由与记忆数据位于所选工作目录的 `.dsh-kook/`，具体路径可以在高级设置中配置。请将这些数据与 Token 留在本机，不要提交到 Git。

## 常见问题

### 在插件详情页找不到完整配置表单

rc5.4 起，请从 DSH 左下角用户菜单进入 **设置 → KOOK**。插件详情页保留版本管理和简洁指引，不再重复放置完整表单。安装更新后若设置菜单尚未出现 KOOK，请先刷新 DSH 页面，并确认插件已启用；无需重新填写已有配置。

### 更新后工作区看不到会话

先刷新 DSH 页面。热更新释放旧会话时，当前页面可能移除实时摘要；刷新后会重新读取持久化列表，原会话和路由仍然保留。`/help`、`/image` 是插件内置命令，本身不会创建模型对话。若刷新后仍异常，可用 `/status` 获取会话 ID 再排查。

### 文字正常，图片没有回复

确认已安装支持图片卡片的版本，并选择支持图片输入的模型。频道同条发图时，检查 @是否选择了**机器人账号**：实际记录已发现同名“Nemo”角色提及导致图片未触发，而后续单独 @机器人发送的文字正常。也要检查用户/频道白名单、@唤醒开关、自动转发及消息是否确实在同一条中。若分开发送，需先执行显式 `/image` 并在两分钟内发图；失败后按对应的同条或两步方式重新发送。

### @或前缀触发后提示 SESSION_OWNED

这说明触发消息已到达插件，但旧版拒绝复用由本地界面持有的活跃会话。rc5.7 在身份、工作目录与预设一致时借用原 Agent，不创建新会话，也不销毁界面拥有的 Agent。如果仍提示冲突，可能是活跃对象已更换或该会话不允许共享；检查本地状态后重试，确实需要独立会话时使用 `@机器人 /new` 或命令前缀加 `/new`。

### 保存设置后任务停止

这是配置应用行为。保存会中断当前 KOOK 任务并重新连接，请尽量在当前回答完成后操作。

### 机器人要求审批，但 KOOK 中无法确认

打开对应的本地 DSH 会话完成审批。此版本不支持 KOOK 远程审批。
