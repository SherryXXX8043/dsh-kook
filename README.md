# DSH KOOK — rc.5 本地适配版

这是基于 [KOOK 官方 dsh-kook](https://github.com/kaiheila/dsh-kook) 0.3.4 制作的本地修改版，**不是官方新发布版本**。包名继续使用 `dsh-kook`，本地版本为 `0.3.4-local.rc5.1`，仅声明支持 **DSH 0.2.2-rc.5**，Node.js 要求 `>=24.9`。

原作者：lspbupt@sina.com。保留原 MIT 许可证。官方原始说明保存在 [上游说明](docs/UPSTREAM-README.md)，其中 rc.3 和 npm 0.3.4 的安装指引属于历史资料；本地版安装请以本页为准。

## 安装本地包

本地修改版没有发布到 npm。先克隆适配分支，并按本文“从源码重建”一节执行构建、测试和打包；随后打开正在使用的 DSH：

1. 进入 **插件 → 安装**。
2. 在安装输入框填写最终压缩包的绝对路径：

   ```text
   /absolute/path/to/dsh-kook/dsh-kook-0.3.4-local.rc5.1.tgz
   ```

3. 完成安装并启用，刷新 DSH 页面。
4. 打开 **插件 → 已安装 → KOOK 机器人（rc.5 本地版）**，找到 **KOOK 机器人**表单。

将示例替换为生成的压缩包绝对路径，Windows 可使用 `C:/Projects/dsh-kook/dsh-kook-0.3.4-local.rc5.1.tgz` 这样的格式。也可以在本地依赖安装和构建完成后，填写克隆目录的绝对路径进行目录安装；安装后不要移动该目录。压缩包方式更适合固定版本使用。

不要在输入框填写 `dsh-kook@0.3.4` 或 `dsh-kook@0.3.4-local.rc5.1`：前者是会被当前 DSH 拦截的官方旧包，后者没有发布到注册表。安装仍可能需要联网下载官方 SDK 等依赖，本包不是离线依赖合集。

同名插件与 `kook` 配置条目继续沿用上游身份，请只运行一个使用同一 Bot Token 的实例。仓库源码不会自行修改 DSH profile；通过插件管理器安装并启用后才生效。

## 与官方上游同步

`main` 保持官方历史，本地适配集中在 `compat/dsh-0.2.2-rc.5` 分支。同步方法及合并后的验证要求见 [上游维护说明](docs/UPSTREAM-SYNC.md)。Fork 关系方便比较改动，但不会自动解决官方更新与本地适配之间的冲突。

## 第一次配置

在 [KOOK 开发者平台](https://developer.kookapp.cn/)创建机器人，选择 **WebSocket**，获取 Bot Token，并将机器人邀请进自己的 KOOK 服务器。开启 KOOK 的开发者模式后复制自己的用户 ID。

在插件表单中：

- 填入 **Bot Token**，只在本地配置页输入。
- 选择一个已存在的 **工作目录**。这是运行 DSH 电脑上的目录。
- **允许的用户 ID** 填你自己的 KOOK 数字用户 ID。
- 打开 **允许私聊**；**允许的频道 ID** 先留空，**自动转发频道消息** 先关闭。
- 模型与 Agent 预设先选 **跟随 DSH 默认**。
- 点击 **保存设置**，然后去 KOOK 私聊机器人发送“你好”。

收到正常回复后，可以测试 `/status`、连续追问、`/stop` 和 `/new`。想在频道里用，再把频道 ID 加入白名单，并发送 `/dsh 你好`。

DSH 运行的电脑需要保持开机、联网；无需额外运行 Satori 网关，也无需公网回调地址。

## 本地版改变了什么

- 版本声明从精确 rc.3 改为已核对的精确 rc.5；保留版本检查机制。
- **跟随默认**时，会话创建或恢复会读取 DSH 默认供应商、模型和推理等级。
- **恢复旧会话时会应用当前插件模型选择，覆盖该会话原先记录的模型与推理等级**。如果你曾在 DSH 界面单独切换该 KOOK 会话模型，下次由插件恢复时仍以插件配置为准。
- 显式指定供应商与模型时，不继承其他模型的全局推理等级，使用所选模型的默认推理等级。
- 运行中的会话不会因为 DSH 全局默认变化而立即切换。保存插件配置会停止当前 KOOK 任务并重连，下一条消息恢复会话并应用新配置。
- 配置页新增保存前的任务停止提示，以及模型策略说明。

修改工作目录或 Agent 预设后，仍可能需要在 KOOK 发送 `/new`。模型选择事件不等于供应商可用性检测；模型凭据或服务异常仍可能在第一次模型请求时出现。

## 验证与限制

回归结果和验证边界见 [验证报告](docs/VALIDATION.md)。通过自动化和静态检查不等于真实机器人联调；请先按上面的私聊流程测试。

- 文字与 KMarkdown 入站、纯文本回复；不支持图片、附件、语音、卡片，非逐 token 流式。
- 审批、计划确认、交互式问题仍在本地 DSH 界面完成。
- 助手过程说明可能与最终回复一并分条发送。
- 保存配置会停止当前 KOOK 任务，等本轮回答完成后再保存。
- 限定当前 rc.5；未来升级 DSH 后，需要重新核对版本及接口。

## 从源码重建

保留本项目目录和锁文件，在具备 Node.js 24.9+ 和 npm 的环境中执行：

```sh
npm ci --ignore-scripts
npm run build
npm test
npm run check
npm pack --ignore-scripts
```

`test/` 是常规隔离回归；`validation/rc5-host.test.mjs` 还需使用 DSH 自带 Electron 运行时和 `validation/runtime-hooks.mjs`，用于针对本机实际 rc.5 库验证模型选择行为。该项验证不会访问真实机器人或调用模型。

## 后续切回官方版

官方发布兼容版本后，先等任务完成并停用本地版，再通过当前 DSH 插件管理器卸载本地包、安装官方兼容包。保留你选择的工作目录中的 `.dsh-kook` 路由与记忆数据；未来官方配置或格式是否变化应以对应版本说明为准。不要同时启用本地版与官方版使用同一 Token。
