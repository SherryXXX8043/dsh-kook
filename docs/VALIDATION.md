- 完整自动化回归 **127 项通过**，包括设置入口/详情指引注册、真实 Cordis 注入、locale 字典注册与卸载、完整配置操作集、Token 保留/替换/停用/环境变量，以及既有图片和通信回归。

## rc5.3 实际客户端兼容修复

真实 KOOK 测试发现：客户端上传的图片可被平台包装为 `type: 10` 卡片，`modules[].type=container` 的 `elements[]` 中含 `type=image, src=<KOOK CDN URL>`；rc5.2 只接收 `type: 2` 因而静默忽略。rc5.3 增加有界图片卡片解析，复用同一授权、下载和附件准入链路，并保留随图文字；普通图片仍支持。

- 完整回归 **116 项通过**，实际宿主验证 **8 项通过**。新增 16 项卡片回归涵盖实际客户端结构、私聊/频道、文字加图片、权限与去重以及解析数量/字节边界。
- 另对用户实际测试卡片进行只读诊断，从原 KOOK CDN 下载图片，在隔离实际 DSH 附件库中完成解码、保存和验证读回：**1 张 PNG，534 × 192**。未替用户重发消息，也未调用模型。
- 工作区空列表：两条原 KOOK 会话及其 Workspace 关联均仍存在，实际持久化实现可枚举、`formatStatus=current`、cwd正确、`blank=false`。DSH 热更新释放旧 live Session 时向页面发 `api-session/removed`，新插件只关联 Workspace，不强制恢复 Agent，因此页面可能暂时缺少 summary；刷新 DSH 页面重新取得冷列表基线。没有修改 Workspace 存储或 DSH 核心，也没有为刷新列表启动历史任务。
- 安装 rc5.3 后，用户在真实 KOOK 私聊执行 `/image` 并发送图片；提供的截图确认模型正确识别出图中文字，回复成功返回 KOOK。随后用户反馈整体使用正常。此证据确认当前环境的私聊图片识别链路；频道收图、向 KOOK 发回图片及各格式仍以各项实际测试范围为准，不扩大为完整端到端矩阵通过。

## rc5.2 图片功能验证

本版本新增 KOOK `type: 2` 图片事件接收、官方 CDN 受限下载、DSH 原生附件校验保存、`/image` 两分钟一次性接图，以及绑定当前 KOOK 会话的 `send_kook_image` 工具（工作区图片校验 → 当前机器人上传 → type 2 发送）。默认频道触发规则保持明确：关闭自动转发时先发送 `/dsh /image <问题>`。

- 常规回归 **100 项通过、0 失败、0 跳过**。包含原有 29 项及图片新增测试，运行于 Node v24.21.0；SDK 0.1.4 对本地 HTTP/WebSocket 服务验证真实 multipart 二进制上传、频道/私聊 type 2 payload、图片事件映射、取消、超时和各类失败不重试。
- 实际安装的 DSH rc.5 / Electron 运行时验证 **7 项通过**：原有 4 项 AgentModel 验证，以及 3 项实际 `LocalAttachmentStore` 的图片完整解码、持久化读回、损坏图片拒绝和数量限制。测试存储隔离在仓库的忽略目录中，不使用用户附件目录。
- 新增回归覆盖：授权先于下载、图片 URL 域名/协议/凭据/跳转限制、流式字节上限、格式签名与完整宿主校验、工作目录实际目标包含检查、用户/频道路由隔离、两分钟过期、重复事件、失败恢复提示，以及 `/stop`、`/new` 在排队/下载/创建会话/记忆保存期间的取消。
- 发送工具只在插件实际管理的 KOOK Agent 中可用，执行和出队时核对 Agent 对象与目的聊天。发送结果未知返回 `unconfirmed`，不自动重投。真实发送测试只访问本地假服务。
- 客户端构建、全部运行模块与构建脚本语法检查、Git diff 空白检查通过。安装包清单核对包含图片模块、客户端构建产物、中英文介绍及使用文档。
- 独立代码与使用流程审查已完成，已修复停止竞态及频道失败重试指引；无剩余阻断意见。设置页只增加图片帮助文字，沿用既有布局和图标。没有浏览器控制，未做实际视觉验收。

运行常规测试：`npm test`；构建：`npm run build`；语法：`npm run check`。实际宿主测试使用 `DSH_NODE_EXECUTABLE`、`ELECTRON_RUN_AS_NODE=1`，参数为 `--import ./validation/runtime-hooks.mjs --test --test-isolation=none validation/image-host.test.mjs validation/rc5-host.test.mjs`。

**rc5.2 交付当时，图片功能尚未通过真实 KOOK 和真实模型端到端验收；rc5.3 的实际验证见上文。** 自动化结果不证明平台在线权限、CDN 可达性、WebP/GIF 上传接受度或当前模型看图能力。收到图片后仍取决于所选模型是否支持图片；当前宿主会把动图规范化为静态图。KOOK API 没有在本次查阅的上传文档中给出机器人图片精确大小上限，8 MiB 是插件自身的保守限制，不是官方限额声明。

- `src/index.js`：完整继承默认模型的 reasoningEffort；在 Agent setup 的未发布阶段显式选择模型，使恢复会话使用当前插件选择。

## 自动化验证

运行环境为当前 DSH 0.2.2-rc.5 自带 Electron 44.7.0 / Node v24.21.0，Cordis 4.1.0，Schemastery 3.19.0；KOOK SDK 0.1.4、ws 8.23.0、pako 2.2.0 按上游锁文件的 SHA-512 校验。

最终测试共 33 项，全部通过、失败 0、跳过 0：上游 24 项、本地回归 5 项、当前 rc.5 AgentModel 验证 4 项。公开仓库保留可复现的验证代码，不提交包含本机路径的测试输出。

用户随后在本机安装本地包并反馈：私聊、指定文字频道回复和网络搜索测试正常。这是用户环境下的使用反馈，不代表其他 DSH 版本、权限组合或所有模型的兼容保证。

覆盖包括：预设及会话参数、连续消息唯一 ID、工作区登记失败 dispose、Cordis 激活与卸载、配置模块服务注入；官方 SDK 对本地 HTTP/WebSocket 假服务的群聊/私聊、鉴权、心跳、断线恢复、取消、超时与错误；模型恢复、默认 effort、相同选择去重、仅 effort 改变与清除旧 effort。

`validation/runtime-hooks.mjs` 仅供审查，将 DSH 包导向本机实际安装库；它不随安装包运行，也不修改生产模块解析。

## 未验证事项

- 自动化验证不包含真实 KOOK Token 或付费模型请求；实际私聊、频道与搜索仅有上述用户反馈，没有完整平台端到端测试矩阵。
- 没有浏览器自动化测试覆盖表单各字段、Token 保留/清空及并发 revision 冲突。
- Agent create/resume 的大部分测试使用模拟服务；真实 AgentModel 测试的 Session append/fold 仍是受控测试对象，不是完整 AgentLoop、持久化服务或真实 Session 集成。
- setup 失败释放完整宿主 scope 的路径只做源码核对；不要把 mock 参数失败测试描述成完整宿主清理测试。
- 图标沿用上游未提供专用图标的情况，使用 DSH 默认图标；未新增预览图。前端视觉和实际图标显示没有浏览器验收。

## 模型策略

本地版有意让创建或恢复使用当前插件选择，可能覆盖曾在 DSH UI 单独修改的 KOOK 会话选择。显式模型没有 reasoningEffort 时清除旧 effort，使用该模型默认。模型选择事件本身不检查供应商可用性；首次真实模型调用才会验证相关凭据与服务。

不使用版本豁免，不放宽到未知未来 DSH 版本，不修改 DSH 安装文件。
